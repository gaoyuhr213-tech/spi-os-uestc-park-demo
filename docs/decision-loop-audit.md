# SPI-OS 决策闭环审计报告（迭代13 · Decision Loop Audit）

**审计基准**：来源提示词（12 模块建议 + Decision Center + Decision Marketplace）、《科创园区决策智能操作系统》商业模式文档（六层收入模型 + 商业飞轮）、北美七家最佳实践（Palantir / 6sense / Salesforce / Workday / ServiceNow / LinkedIn / ZoomInfo）。

**北极星**：Every Enterprise Need Becomes a Decision. Every Decision Triggers the Right Resource. Every Resource Creates Measurable Outcomes.

---

## 一、Executive Summary

**核心结论：现有原型在「需求识别」环节已达半闭环以上水平，但「决策」在系统中不是一等对象——建议（NBA）是文本、匹配靠人工、结果无归因、学习断在决策层。** 六环节判定：识别（✅ 强）→ 决策生成（⚠️ 半：有 NBA 文本但无决策对象）→ 资源匹配（❌ 断：无资源库、无匹配引擎）→ 执行（⚠️ 半：有任务打卡但与决策脱钩）→ 结果量化（⚠️ 半：有成交/流失原因但无决策级 ROI）→ 学习沉淀（⚠️ 半：飞轮只校准评分规则，不校准决策类型）。

**升级主张：不加新页面。把「决策」升级为数据库一等对象（decisions 表），打通 Signal → Need → Decision → Match → Execute → Outcome → Learning 七段流水线，屏一升级为 Decision Center，企业360 决策 Tab 补需求画布+生命周期+资源匹配，任务页承接决策执行，飞轮增加决策级学习。**

## 三、六环节逐项审计（对标北美）

### 1. 需求识别（Identify）— 判定：✅ 基本闭环
- 已有：信号→意图标签→需求预测（岗位方向/数量级/时间窗/置信度）。
- 对标 6sense（Intent Data → Buying Stage）：**缺「需求画布」**——需求只有招聘一个维度，未覆盖人才/融资/政策/市场/研发/数字化/法务七类；**缺企业生命周期阶段**（Pre-A 默认缺融资+招聘+股权，IPO 默认缺董秘+法务+券商），生命周期即需求先验。

### 2. 决策生成（Decide）— 判定：⚠️ 半闭环（最大断点）
- 已有：NBA 是 buildNba() 生成的**一段文本**，不可采纳、不可指派、不可追踪、不可统计。
- 对标 Palantir（Decision as First-Class Object）/ ServiceNow（每个建议都是可流转的 Record）：**决策必须对象化**——每条建议 = 一条 decision 记录（类型/对象企业/原因链/星级/状态机：建议→已采纳→执行中→已完成/已放弃）。
- 对标来源提示词 Decision Center：今日建议应按决策类型分组聚合（立即联系/安排导师/推荐HR咨询/政策申报/校友引荐），带原因与星级，而非散落各屏。

### 3. 资源匹配（Match）— 判定：❌ 断点（完全缺失）
- 现状：话术里写死「信软学院管道」「高于人力」，无资源库、无匹配逻辑。
- 对标 LinkedIn（Graph-based Matching）/ ZoomInfo（Data→Routing）：需要 resources 表（导师/猎头/校友/教授/投资人/律所/财税/服务商，含能力标签与容量），匹配引擎按「需求类型×行业×阶段」自动出 Top-N 推荐，并与暖引荐图谱链路复用（谁介绍谁）。
- 商业含义：这就是六层收入模型第三层 Marketplace 的产品底座——无资源匹配则撮合佣金无从谈起。

### 4. 执行（Execute）— 判定：⚠️ 半闭环
- 已有：任务清单（首触/复访/培育）与打卡，但任务由规则推演，**与具体决策无关联**——打卡不知道完成的是哪条决策。
- 对标 Salesforce（Opportunity→Task 强关联）：采纳决策应生成执行任务（负责人+期限），打卡回写决策状态。

### 5. 结果量化（Outcome）— 判定：⚠️ 半闭环
- 已有：成交/流失原因编码，漏斗按企业聚合。
- 缺：**决策级 ROI**——每类决策的采纳率/执行率/带来成交数/归因收入（映射六层收入：订阅/AI能力/撮合佣金/运营/咨询），无法回答「校友引荐的成功率是不是 92%」。

### 6. 学习沉淀（Learn）— 判定：⚠️ 半闭环
- 已有：飞轮校准评分权重。
- 缺：**决策类型级学习**——哪类决策在哪类企业上有效/无效，应回写为决策生成的先验（如「路径B引荐在软件类 P0 成功率高 → 星级上调」），保持人在环。

## 五、实施范围（迭代13，不加新页面）

1. **decisions 表 + 决策引擎**：由信号/意图/预测/生命周期阶段自动生成决策对象（5类：立即联系/安排导师/HR服务/政策申报/暖引荐），含原因链、星级、状态机。
2. **需求画布 + 生命周期**：7 类需求强度（1-5星）由信号与富集推断；9 段生命周期阶段推断（阶段→默认需求先验）。
3. **resources 表 + 匹配引擎**：资源库播种（导师/猎头/校友/投资人/律所/财税/高于人力等），按需求×行业×阶段匹配 Top-3，复用图谱引荐链路。
4. **Decision Center**：屏一顶部升级为今日决策建议流（分组+原因+星级+采纳→指派）；企业360 决策 Tab 加需求画布+阶段+资源推荐；任务页承接决策执行；飞轮加决策类型命中统计。
5. **Outcome 归因**：决策级统计 API（采纳率/执行率/成交转化/归因收入分层）。

全程保持既有公理：核心逻辑后端计算、人在环、台账留痕、双主题、脱敏、i18n。
