## 3. 详细数据

### 3.1 评分复算

5 次连续复算耗时：411ms, 103ms, 101ms, 95ms, 86ms

- 首次较慢（冷启动 + 连接池建立），后续稳定在 100ms 以内
- P95 = 411ms，远低于 2,000ms SLA
- 读时计算架构优势：无需预计算存储，实时响应

### 3.2 图路径查询

20 次随机路径查询：P95 = 27ms

- 当前图规模（2,069 节点 + 100 边）下查询极快
- 预估 10,000 节点 + 500 边仍可保持 < 100ms（线性增长）

### 3.3 Pipeline 吞吐

- 全量快照（含评分计算）：88ms / 2,069 实体
- 吞吐：23,511 实体/秒
- 无背压风险（远低于 30s 阈值）

## 4. 瓶颈分析与优化

| 瓶颈点 | 现状 | 优化措施 | 效果 |
|--------|------|---------|------|
| 首次复算冷启动 | 411ms | 连接池预热（已由 drizzle lazy init 处理） | 后续 < 100ms |
| 大批量 INSERT | loadgen 1,806ms/2000 实体 | batch=100 分批写入 | 稳定无超时 |
| 图查询 | 27ms P95 | 当前无需优化（远低于 SLA） | — |

**索引现状：** entities.eid（主键）、enrichments.eid（唯一）、graphEdges.fromKey/toKey（已有索引）——当前规模下无需额外索引。

**缓存策略：** 评分为读时计算（无缓存），在 2,000 实体规模下仍 < 500ms；若未来扩展到万级，建议对 buildSnapshot 结果加 TTL 缓存（60s）。

## 5. 扩展性预估

| 规模 | 预估复算耗时 | 预估路径查询 | 建议 |
|------|------------|------------|------|
| 5,000 实体 | < 1s | < 50ms | 无需优化 |
| 10,000 实体 | < 2s | < 100ms | 考虑快照缓存 |
| 50,000 实体 | 5-10s | < 300ms | 必须加缓存 + 分页快照 |
